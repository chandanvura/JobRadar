# v0.1.0 — maintenance baseline

Prepared on 21 October 2026 for the first public versioned release. This records
the existing application baseline; it is not evidence of external adoption or a
claim that every feed is healthy. The GitHub release and tag identify the exact
published revision when these notes are published.

## Included

- Python employer collection with bounded retries and snapshot reconciliation.
- React/TypeScript frontend and Cloudflare Worker/D1 API, with Bengaluru/Hyderabad
  browsing and strict posting-date and 0–3 years JD evidence rules.
- Private browser application tracking and validated backup import/export.
- Existing static fallback, scan recovery, notification diagnostics and daily
  SQL exports verified through disposable SQLite restore checks.
- Protected PR validation, CodeQL, dependency checks and security reporting.
- Root MIT license and a maintenance-scoped contributor guide. Existing
  third-party notices remain in place.
- Lenovo singular last-page label repair from PR #89, without weakening count,
  unique-ID, detail or final-snapshot checks.

## Validation and known limits

The collector baseline from PR #89 passed 974 Python tests, Bandit, runtime
dependency audit and all six GitHub checks, including `python`, `web` and CodeQL.
The Lenovo repair collected 61 listings and 23 relevant details in a bounded
read-only local adapter probe; this is not completed production recovery evidence.

The latest verified finalized production scan in this review is run
[39589334236](https://github.com/chandanvura/JobRadar/actions/runs/39589334236):
740/743 sources succeeded. [Issue #87](https://github.com/chandanvura/JobRadar/issues/87)
tracks AXA's HTTP 403, Citigroup's incomplete recovery verification (a later
read-only detail probe hit HTTP 429), and Lenovo's next completed production scan.
The Citigroup listing-only probe returned 605 unique IDs; it does not prove full
source recovery. Prior source data is retained. Gate-only runs are not collection
evidence. No release-time production scan is manually dispatched.

Private browser history needs its own Settings export; SQL backups cannot restore
cleared browser data. Provider changes, credential expiry and infrastructure
limits can require intervention. No uptime or nine-month zero-maintenance guarantee
is made, and no downstream adoption metrics have been verified.

## Maintenance policy

Feature development remains frozen. Keep existing companies and the current
stack. Future changes are limited to reproduced security, data-integrity or
existing-functionality repairs. Follow [CONTRIBUTING.md](../../CONTRIBUTING.md),
[SECURITY.md](../../SECURITY.md) and the [readiness review](../READINESS-REVIEW.md).
This release does not itself deploy the application or claim a new production build.
