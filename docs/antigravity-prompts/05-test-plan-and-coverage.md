Use the `test-engineering` skill.

Inspect current tests and test tooling first. Build a test matrix mapping requirements to unit, integration, contract, browser/E2E or manual checks. Identify missing coverage, flakiness and overly coupled tests. Add tests that assert observable behavior, including invalid inputs, boundaries and failure modes. Run focused tests, then the broader relevant suite. Do not weaken assertions or skip tests just to get green. Report what is covered and what remains unverified.
